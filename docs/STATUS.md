# Current project state

Updated 2026-11-27. Compact entry point; source/settings and fresh Editor evidence take precedence. This summary is not a substitute for validation after changes.

- **Product:** portfolio-grade third-person Motion Matching locomotion. Papers guide implementation; playable movement quality is the deliverable.
- **Implemented:** foundation, source consolidation, legacy cleanup, M2 database baking, M2.5 inspection/preview, M3A/M3B query/search and M3C live matching/Playables integration. The user-authorized experimental M3C component is enabled and saved in MotionMatchingTest; polished playable acceptance remains open. The five project assemblies remain unchanged; newly imported Kevin Iglesias content includes two reviewed third-party C# sources outside them. `MotionMatchingTest` is the sole enabled build scene.
- **Gameplay:** opt-in matching uses one Playables graph containing the retained action controller and matched clips. Grounded input yaw is capped by the saved/default `TurnRadiansPerSecond=1.57` rad/s; root yaw is experimental. The controller branch has zero weight during grounded matching and remains available for actions/fallback. RootMotionRelay submits horizontal motion; CharacterMotor owns capsule Move; gravity advances independently in PlayerController.LateUpdate.

It has no 180-degree turn clips. The nine-clip `LocomotionBaseline.asset` (1,026 rows; 906 searchable, including two 180-degree turns) is preserved as `PreviousDatabase` for rollback. Six authored actions/idle transitions from the 31-clip Movement inventory are excluded; their per-value audit export is pending. Contacts and transition suitability remain unverified. Menu: Tools > Motion Matching > Motion Database Baker.

Old-database stall captures precede the world-scale fix and are not final new-database metrics. Final capture and Player validation remain open. See [hardening report](migration/M3C_HARDENING_REPORT.md).
